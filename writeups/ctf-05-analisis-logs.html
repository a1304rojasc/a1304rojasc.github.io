Reto 05: encontrar al atacante que sí entró

Me dan el auth.log de un servidor y hay que responder: ¿qué IP consiguió entrar por fuerza bruta, y con qué usuario?

1. Contar fallos por IP

grep "Failed password" auth.log | grep -oE "from [0-9.]+" | sort | uniq -c | sort -rn
    120 from 45.155.205.9
     85 from 198.51.100.23
      7 from 192.168.1.22
      7 from 10.0.0.5
      5 from 192.168.1.15

Dos IPs destacan muchísimo. Los 5 a 7 fallos de las IPs internas son usuarios que se equivocan al escribir: es ruido normal.

2. ¿Alguna de las dos consiguió entrar?

grep "Accepted password" auth.log | grep -E "45\.155\.205\.9|198\.51\.100\.23"
Nov  1 14:50:42 srv-web01 sshd[28819]: Accepted password for soporte from 198.51.100.23 port 55443 ssh2
  • 45.155.205.9 falló 120 veces y se rindió. Es el distractor: hace mucho ruido pero no entró.
  • 198.51.100.23 falló 85 veces en unos 3 minutos y después entró como soporte.

3. Lo mismo en Python

import re
from collections import Counter

fallos, exitos = Counter(), []
for linea in open("auth.log"):
    if m := re.search(r"Failed password for (?:invalid user )?\S+ from (\S+)", linea):
        fallos[m[1]] += 1
    elif m := re.search(r"Accepted password for (\S+) from (\S+)", linea):
        exitos.append((m[2], m[1]))

print([(ip, u) for ip, u in exitos if fallos[ip] > 20])

Flag: CENTINELA{…} (oculta para no arruinar el reto).

Lección

Lo urgente no es la IP con más fallos, sino una racha de fallos que termina en un éxito. Esa idea es el núcleo de Centinela, que lo automatiza con una ventana de tiempo. Ojo: este parser rápido usa \S+ para el usuario, y la auditoría explica por qué eso se puede engañar.
