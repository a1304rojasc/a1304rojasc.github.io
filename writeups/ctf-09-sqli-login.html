Reto 09: entrar como admin sin contraseña

Una tienda de prueba, que corre solo en 127.0.0.1, tiene un login. Tengo la cuenta invitado, pero el panel solo lo ve admin. Además, un "modo depuración" muestra la consulta SQL que se ejecuta.

1. ¿Es inyectable?

En el usuario escribo solo una comilla: '. La app responde con un error de base de datos y enseña la consulta rota. Mi comilla desequilibró las del SQL, así que el campo se está pegando dentro de la consulta:

SELECT id, username, rol FROM usuarios
WHERE username = 'LO_QUE_ESCRIBO' AND password = 'LO_QUE_ESCRIBO'

2. Comentar la contraseña

En el usuario escribo admin' -- (con un espacio al final) y cualquier contraseña:

SELECT id, username, rol FROM usuarios
WHERE username = 'admin' -- ' AND password = '...'

Todo lo que va después de -- es un comentario, así que la comprobación de la contraseña desaparece. Entro como admin y aparece la flag: CENTINELA{…}.

Detalle instructivo

El clásico ' OR '1'='1' -- también entra, pero como invitado. La condición es cierta para todas las filas y la base de datos devuelve la primera (id 1). El ataque dirigido es mejor: no solo entras, entras como quien quieres.

El arreglo

La causa es mezclar datos del usuario con código SQL. La solución son las consultas parametrizadas: el valor viaja aparte y la base de datos nunca lo interpreta como código.

db.execute(
    "SELECT id, username, rol FROM usuarios WHERE username = ? AND password = ?",
    (usuario, contrasena),
)
Además: nunca guardar contraseñas en claro (usar un hash lento como Argon2) y nunca dejar un modo depuración activo en producción.
